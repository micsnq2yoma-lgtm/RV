# 仿真机器人 Agent Demo 设计：RV 板子控制 MuJoCo 里的 Franka Panda

- **作者**：Claude
- **日期**：2026-11-08
- **人的决定**：大模型用 DeepSeek-V4.1-Flash（API 里实际的模型 ID 是 **`deepseek-flash`**，报告 009 已核实；`DeepSeek-V4.1-Flash-1017` 这个 ID 在 API 里不存在）；机械臂用 **Franka Panda**（MuJoCo Menagerie 模型）。
- **S0 实测（报告 009）**：工具调用和 JSON 输出都正常，从板子发请求平均约 1.2 s；能接收图片格式，但一张纯红色图片被认成了 White。**因此不依赖它的视觉能力**，感知一律走板子上的 L3，用文字描述场景。
- **灵感来源**：ESP32 iPhone Agent by Henry Yuan（https://github.com/onehumanbeing/esp32-iphone-agent ，MIT 协议）的“看屏幕 → 想 → 动手 → 再看”闭环。本项目不复制它的代码；如果以后借用其中的提示词或代码，要保留它的 MIT 版权声明，并注明出处。

## 1. 目标

桌上有红、绿、蓝三个方块和两个托盘。人输入一句话，比如“把红色方块放进左边的托盘，再把蓝色叠到绿色上面”。RV 板子上的 Agent 观察场景、规划动作、控制 Panda 执行，每做完一步检查结果，直到任务完成或者明确失败。

- 电脑：只负责物理仿真、渲染和显示画面。
- RV 板子：负责感知、规划（调用 DeepSeek）、运动学和实时控制。

以后把仿真换成真机械臂（EtherCAT 伺服），上面三层都不用改。

## 2. 架构

```
┌─────────── 电脑（Windows）───────────┐      网线 J1/eth0      ┌──────────────── RV 板子 ────────────────┐
│ MuJoCo：Panda + 桌子 + 方块 + 托盘     │  192.168.50.1 → .50.2  │ L1 实时控制（C，SCHED_FIFO）             │
│  · 物理步长 2 ms（500 Hz）             │ ─UDP 状态 250 Hz────▶ │   收状态 → 轨迹插补 → 回关节目标          │
│  · 位置伺服执行器（关节 1–7 + 夹爪）    │ ◀UDP 关节目标──────── │ L2 技能（Python）                        │
│  · 相机：top（俯视）、wrist（腕部）     │ ─TCP 图像/真值──────▶ │   逆运动学；pick / place / move_to / home │
│  · 可视化窗口（演示用）                │                        │ L3 感知（Python）                        │
│ sim_server.py（主动连接板子）           │                        │   俯视图颜色分割 → 像素 → 桌面坐标        │
└───────────────────────────────────────┘                        │ L4 Agent（Python）                       │
                                                                  │   场景描述 → DeepSeek → 技能调用 → 校验    │
                                                                  │ L5 网页面板（任务输入、步骤回放）          │
                                                                  └──────────────────┬─────────────────────┘
                                                                                     │ SSH 反向隧道代理（任务 008）
                                                                                     ▼ api.deepseek.com
```

### 设计要点

1. **连接方向：电脑主动连 RV 板子。** RV 板子在 `192.168.50.2` 上监听，电脑只往外发包，**不需要修改 Windows 防火墙**（任务 008-r2 就是改防火墙导致电脑断网）。UDP 回包靠 Windows 防火墙的状态跟踪放行。
2. **快慢分层。** 大模型每次调用要几秒；L1 实时控制环和它在**不同进程**、不同优先级里运行，Agent 等待网络时，机械臂照样平稳运动或保持不动。
3. **感知放在 RV 板子上。** DeepSeek-V4.1-Flash-1017 是否支持图片输入**尚未确认**（S0 会测）。所以默认方案是：板子对俯视图做颜色分割，把结果整理成文字场景描述（物体、颜色、桌面坐标、在哪个托盘里）发给模型。如果模型支持图片输入，再把图片一起发过去作为补充。
4. **用真值评估。** 仿真端可以提供物体的真实位姿，**只用来评估和调试**，比如检查感知误差、判定任务是否成功。Agent 做决策时默认不用真值，可以通过开关打开，用于排查问题。
5. **安全约束。** 关节目标要限位、限速；如果 100 ms 收不到指令，仿真端就保持当前位置，和真机的看门狗逻辑一致，方便以后换成真机。

## 3. 通信协议 v1（S1 和 S2 都按这个实现）

### 3.1 UDP 控制通道：RV 板子 `192.168.50.2:15001`

全部用**小端**、定长二进制结构。

**状态包 `RVS1`（电脑 → 板子，每 4 ms 一个，即 250 Hz）**

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | char[4] | `"RVS1"` |
| 4 | uint32 | seq：从 0 开始递增 |
| 8 | float64 | sim_time：仿真时间（秒） |
| 16 | float64[7] | q：关节 1–7 的位置（rad） |
| 72 | float64[7] | dq：关节 1–7 的速度（rad/s） |
| 128 | float64 | gripper：两指张开总宽度（m，0–0.08） |
| 136 | uint32 | flags：bit0 = 指令已超时，进入保持；bit1 = 刚复位 |
| 140 | uint32 | last_cmd_seq：最近一次应用的指令序号 |
| 144 | — | 总长 144 字节 |

**指令包 `RVC1`（板子 → 电脑，每收到一个状态包回一个，发往状态包的源地址和端口）**

| 偏移 | 类型 | 字段 |
|---:|---|---|
| 0 | char[4] | `"RVC1"` |
| 4 | uint32 | seq：板子自己的递增序号 |
| 8 | uint32 | ack：所响应的状态包 seq |
| 12 | uint32 | mode：0 = 保持当前位置，1 = 关节位置控制 |
| 16 | float64[7] | q_des：关节目标位置（rad） |
| 72 | float64 | gripper_des：夹爪目标宽度（m，0–0.08） |
| 80 | — | 总长 80 字节 |

仿真端每步都用最近一次收到的指令。超过 100 ms 没收到指令，就进入保持（flags bit0 = 1）。往返延迟用 `seq` 和 `ack` 计算。

### 3.2 TCP 服务通道：RV 板子 `192.168.50.2:15002`

电脑连上来以后保持连接，断开就每 2 秒重连一次。每行一个 JSON，**板子发请求，电脑回应答**，应答带上同样的 `id`。

| 请求 `op` | 参数 | 应答 |
|---|---|---|
| `hello` | — | `{"sim":"mujoco","version":"x.y","robot":"panda","cameras":["top","wrist"]}` |
| `render` | `camera`、`w`、`h` | `{"jpeg_b64":"...","w":..,"h":..,"fovy":..,"cam_pos":[..],"cam_xmat":[..]}`：带上相机参数，供像素到桌面坐标的换算使用 |
| `objects` | — | `{"objects":[{"name":"red_cube","pos":[x,y,z],"quat":[w,x,y,z]},...]}`：真值，只用于评估 |
| `reset` | `seed`：可选，用来打乱方块位置 | `{"ok":true}` |
| `ping` | — | `{"t":<电脑时间>}` |

坐标系：MuJoCo 世界坐标，单位米，桌面高度在场景文件里固定，并写进 `hello` 应答（字段 `table_z`）。

### 3.3 协议 v1.1 补充（2026-11-08，根据报告 010）

v1 的字段和长度不变，下面几条只是补充，两端都按此实现：

1. **序号回绕或重启**：任何一端收到的 `seq` 比上一个小时，视为对端刚重启或刚复位，统计从头开始，**不算丢包**。仿真端 `reset` 后 `sim_time` 也归零，flags bit1 置 1。
2. **看门狗**：仿真端在**每个物理步**检查“距上次收到指令的时间 ≥ 98 ms”就保持。100 ms 是在仿真进程正常调度前提下的目标；仿真进程自身卡顿造成的超时，要记录为“仿真端卡顿”，和“板子没发指令”分开统计。
3. **JSON 错误应答**：`{"id":<原 id>,"error":"<原因>"}`。
4. **新增 TCP 请求 `ee_pose`**：返回 `{"pos":[x,y,z],"quat":[w,x,y,z],"q":[7 个关节角],"gripper":<宽度>}`。其中 `pos`、`quat` 是 Panda 夹爪中心点（TCP，两指之间、指尖往回 1 cm 处，由仿真端在场景里定义一个 site）在世界坐标下的位姿，用来校验板子上的运动学。
5. **新增 TCP 请求 `kinematics`**：返回从仿真模型里导出的运动学链：各 body 相对父节点的 `pos`、`quat`，各关节的轴向和限位，以及 TCP site 相对 hand 的偏移。板子据此做正、逆运动学，**不手抄 DH 参数**，保证和仿真模型完全一致。

### 3.4 验收阈值修订

- 板子端每包处理时间：最大值 < **1 ms**（控制周期是 4 ms）。原来的 200 µs 定得过严，报告 010 实测平均 176 µs，最大 490 µs，不影响控制。
- 仿真端：10 分钟内**看门狗误触发 0 次**，状态包到达间隔最大值 < **50 ms**。报告 010 出现过 0.15–1.65 s 的停顿，要在任务 011 里排查。

### 3.5 协议 v1.2 补充（2026-11-08，供 S4 的面板使用）

1. 场景新增两个固定相机：`front`（正面，略俯视）和 `side`（侧面）。`hello` 返回的 `cameras` 变成 `["top","front","side","wrist"]`。
2. `render` 的分辨率放宽到 `w,h ∈ {320×240, 640×480}`。
3. 新增 TCP 请求 `render_multi`，参数为 `cameras`（列表）、`w`、`h`，应答为 `{"images":{"top":{"jpeg_b64":..,"fovy":..,"cam_pos":..,"cam_xmat":..},...}}`。用一次往返拿到多个视角的图像，供面板刷新使用。
4. 渲染始终在仿真端的渲染进程里完成，**不能影响物理步进**（任务 011 修复后的结构）。

## 4. 各层说明

- **L1 实时控制（C）**：`rt_ctl`，线程用 `SCHED_FIFO` 优先级 80，并 `mlockall`。收到状态包后，按当前轨迹段做五次多项式插补，算出 `q_des` 后立即回包。轨迹段由 L2 通过本地 Unix socket 下发（起点、终点、时长）。统计周期抖动和丢包，按秒输出。
- **L2 技能（Python）**：Panda 的正、逆运动学，用改进 DH 参数加阻尼最小二乘数值逆运动学，numpy 实现。技能包括 `move_to(x,y,z,yaw)`、`pick(x,y)`、`place(x,y,z)`、`gripper(open|close)`、`home()`。抓取流程：先到物体上方 10 cm，下降，闭合夹爪，抬起；用夹爪宽度判断有没有抓住。
- **L3 感知（Python）**：用 `render top` 拿到俯视图，在 HSV 空间做颜色阈值分割，取连通域质心，再用相机参数做射线和桌面求交，得到桌面坐标。托盘也一样识别。输出场景描述的 JSON。
- **L4 Agent（Python）**：调用 OpenAI 兼容接口，`base_url=https://api.deepseek.com`，模型 `deepseek-flash`，用 function calling 把技能暴露给模型；如果模型不支持工具调用，就退回到要求模型输出 JSON。每一轮：感知 → 场景描述 → 模型选一个技能 → 执行 → 重新感知并告诉模型结果。最多执行 N 步；模型调用 `finish` 时结束。每一步都记录到 `runs/<时间>/steps.jsonl`，并保存截图。
- **L5 网页面板**：FastAPI，监听 `192.168.50.2:8080`，电脑浏览器打开。可以输入任务、看实时俯视图、查看步骤回放。

## 5. 运行环境

- 电脑：Python 3.11+，`pip install mujoco numpy`，模型用 MuJoCo Menagerie 的 `franka_emika_panda`。
- RV 板子：L1 用 Buildroot 或 Ubuntu chroot 里的 gcc 编译；L2–L5 在 eMMC 上的 Ubuntu chroot 里运行（`python3-numpy`、`python3-pil`、`python3-fastapi`、`python3-uvicorn`、`python3-httpx`，用 apt 装，走任务 008 的代理）。
- **DeepSeek API Key**：由人提供，**不进仓库、不进日志**，只存放在 eMMC Ubuntu 里的 `/root/.config/rv-agent/deepseek.key`（权限 600），运行时读取。
- 大模型的网络访问：通过 SSH 反向隧道使用 `http_proxy=http://127.0.0.1:7897`（任务 008-r3）。控制和感知都不依赖外网，只有 L4 需要。

## 7. 风险

| 风险 | 应对 |
|---|---|
| DeepSeek-V4.1-Flash-1017 不支持图片输入 | 默认就用文字场景描述（L3 在板子上做感知），不依赖图片输入 |
| 不支持 function calling | 退回到“输出 JSON + 校验”的方式 |
| 板子上 Python 太慢 | 实时环用 C；Python 只跑 10 Hz 以下的逻辑 |
| 实时周期被干扰（RT throttling） | Agent 和 apt 不能占用实时核；测周期抖动；必要时把 `rt_ctl` 绑定到 CPU1 |
| eth0 是百兆网口 | 控制包 144/80 字节，250 Hz 只占约 0.5 Mbit/s；图像按需传，一张约 50 KB |
