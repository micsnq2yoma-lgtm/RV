# 工作台（Dashboard）设计规范 v2

- **作者**：Claude
- **日期**：2026-11-08
- **样稿**：`sim_agent/design/workbench_mockup.html`，单文件，浏览器直接打开。数据是模拟的，但会自动播放一遍完整的“按图叠放”流程，其中包括一次抓取失败和重新规划。
- **视觉参考**：RAX 项目主页（https://robot-agent-exploration.com/ ，“Scaling Online Exploration for Robot Agents”）。参考的是它的会话回放组件：左边是视频，右边是“当前在做什么”，状态用颜色区分，引用智能体的原话，下方是带时间戳、逐行出现的活动日志。本项目只借鉴这种呈现方式，**不使用对方的 logo、名称、文案或素材**。

## 1. 设计目标

录屏或演示时，**一屏（1920×1080）**之内要让观众一眼看清三件事：

1. **任务**：要做什么。如果有目标图片，图片和板子识别出的结果放在一起显示。
2. **智能体的实时规划**：它怎么想（原话）、计划是什么、做到第几步、哪一步失败了、怎么重新规划。
3. **主板信息**：RV 板的两个 CPU 核分别在干什么、实时环是否健康、内存、网络和中断。

风格上要避开现在“深蓝底加荧光青”的 AI 风。改用研究项目页那种干净、以数据为主的风格：**默认浅色**，可以切换深色；大量留白，配 1px 细线和 12px 圆角卡片；颜色只用来表达状态。

## 2. 视觉规范（design tokens）

- **字体**：正文用 Archivo，中文回退到系统字体（PingFang SC、Microsoft YaHei）；品牌字用 Unbounded 800；日志、代码、工具调用用 JetBrains Mono。三种字体都是 OFL 许可证，**正式实现要把 woff2 文件放进仓库，从板子本地加载**，同时附上许可证文件，不依赖外网。
- **数字**：一律 `font-variant-numeric: tabular-nums`。
- **颜色语义固定**，所有组件都一样：青 = 观察/进行中，紫 = 规划/思考，琥珀 = 执行/调用，绿 = 成功，红 = 失败。
- **动效克制**：新的日志行淡入，当前步骤的编号有一圈呼吸光，智能体原话逐字出现。不要渐变背景、发光边框或粒子效果。

## 4. 组件说明

### 4.1 任务条
- 两种任务类型，用分段按钮切换：**单步指令**（自由文本）、**按图叠放**（选择或上传目标图片）。
- 按图叠放时，左侧显示目标图片，右侧显示**板上识别结果**，用色块 chips 表示，例如“蓝 → 红 → 绿（自下而上）· 橙留在桌面”。识别有歧义时，用琥珀色提示“识别不确定”。
- 统计实时更新：步数、已用时间、模型调用次数、token、重新规划次数。

### 4.2 主视角
- 四个视角：front、top、side、wrist，默认主画面是 front。点缩略图就和主画面互换。
- 底部字幕和智能体面板同步：阶段（带颜色）、当前步骤标题、工具调用原文。进度条按技能的预计时长推进，技能结束时跳到 100%。
- 可选叠加：在 top 视角上画出**板上感知**的结果（检测框和名称）。叠加内容由板子计算，用来证明感知是在板子上做的。

### 4.3 智能体面板
- kicker：`智能体 · <阶段> · 第 N 步`，颜色跟着阶段变。
- 原话：模型返回的思考文字（`content`，如果模型有 `reasoning_content` 也一并显示），**用流式接口逐字显示**。
- 计划清单：来自 `update_plan` 工具。每次重新规划时，旧计划里没完成的步骤划掉并标“已替换”，下面插入“第 N 版计划 · <原因>”分隔行和新的步骤。

### 4.4 活动流（agent.log）
- 每行 = 时间 + 类型 + 内容。类型有：感知（青）、思考（紫，斜体）、计划（紫）、调用（琥珀）、结果（绿）、失败（红）、主板（灰，只在关键时刻插入，比如 CPU 峰值或实时环超阈值）。
- 新行高亮，自动滚到底部；用户手动往上翻时暂停自动滚动。

### 4.5 主板
- 数据来自 `sysmon`，每秒刷新一次。实时环折线上画出 1 ms 阈值线，超过阈值的点显示成琥珀色或红色。
- 顶栏的“实时环正常”chip：最近 10 秒内处理峰值 < 1 ms 并且丢包为 0 时是绿色，否则变成琥珀色或红色。

### 4.6 回放
- “回放已完成的任务”打开一个列表。选中一个任务后，整个工作台切换成回放模式：主视角显示该任务每一步保存的四张图，计划和日志按步骤逐步展开。底部出现一排步骤点（同 RAX 的章节点），点击跳到对应步骤。顶栏显示“回放中 · <任务名>”，以及“回到实时”按钮。

## 5. 数据流（同时也是性能优化）

任务 014 实测：运行期间 CPU0 平均 99.5%，完整感知一次 1.13 s，每个任务还有约 35 s 的 Python 启动时间。新的数据流：

```
浏览器（在电脑上）
  ├─ 视角画面 ← http://127.0.0.1:8090/stream/<cam>.mjpg   ← 电脑上的 sim_server（MJPEG，直接推给浏览器）
  └─ 页面、事件、主板数据 ← http://192.168.50.2:8080         ← RV 板（HTML/JS/字体静态文件 + SSE 事件流）
```

- **视频不再经过板子转发**：板子只在感知时按需取 top/front/side 图（每步一次），不负责面板刷新。
- 智能体改成**常驻 worker 进程**：dashboard 启动时就把 numpy、感知、IK 都加载好，每个任务不再重新启动 Python。
- 事件通过 **SSE**（`/events`）推给浏览器，格式见任务单 015 的附录。主板数据也走同一条通道。

## 6. 不做的事

- 不做花哨的 3D、渐变和发光效果；不用前端构建工具（原生 HTML/CSS/JS 就够了）。
- 不在页面上提供执行任意命令的入口；不显示 API Key。
