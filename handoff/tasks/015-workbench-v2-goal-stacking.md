## 目标

1. 按设计规范和样稿重做工作台，一屏之内能清楚看到**任务、智能体的实时规划过程、主板信息**。
2. 降低板子负载：视频改由电脑直接推给浏览器，智能体改成常驻进程。
3. 新增任务类型 **“按图叠放”**：给一张目标图片，智能体要照着图上的顺序把积木叠起来。初始状态会故意布置得不利，比如积木的顺序是反的，需要先拆再搭，这样才能体现智能体的规划能力。
4. 补完任务 014 剩下的验收：T3、停止、回放。

## 步骤

### A. 性能结构调整（先做，再改 UI）

1. **电脑端 MJPEG**：`sim_server.py` 增加参数 `--mjpeg 127.0.0.1:8090`，提供 `GET /stream/{top|front|side|wrist}.mjpg?w=&h=&fps=`。主视角 640×480，缩略图 320×240，默认 8 fps。渲染仍然在渲染进程里，**不能拖慢物理步进**。只监听 127.0.0.1，不需要改防火墙。
2. **板子的面板不再转发视频**：删掉 `/video` WebSocket 和后台的 `render_multi` 循环。页面里的视角画面直接用 `<img src="http://127.0.0.1:8090/stream/front.mjpg">`。浏览器就在电脑上，所以可以直接访问电脑本机的地址。
3. **智能体常驻**：dashboard 启动时创建一个 worker 进程，提前加载 numpy、感知、IK 和技能，之后的任务通过队列下发，不再每次 `Popen` 一个新的 `agent.py`。
4. **事件推送**：新增 `GET /events`（SSE），把智能体事件和每秒一次的主板数据都通过它推给浏览器。事件格式见本文末尾附录。
5. 验收：用 T1 跑 3 次，对比改动前后（任务 014 的数据）的 CPU0 平均占用和峰值、单个任务的总耗时，以及 `rt_ctl` 每包处理时间的峰值。**目标：CPU0 平均 < 75%，单个任务总耗时比 014 少 30 s 以上。**

### B. 工作台 v2（UI）

6. 照着设计规范和样稿重写 `dashboard.html`（可以拆成 `static/` 下的 css/js 文件），接上真实数据：
   - 把字体 woff2 和 OFL 许可证放到 `sim_agent/board/agent/static/fonts/`，从板子本地加载；
   - 布局、配色、字体、组件都按规范实现：任务条、主视角加缩略图、智能体面板、活动流、主板卡片、浅色和深色主题；
   - **规划过程**：智能体面板的原话逐字显示（对 DeepSeek 调用 `stream=True`，把文字增量通过 `think_delta` 事件推给浏览器）；计划清单根据 `update_plan` 渲染，重新规划时显示版本分隔；活动流按类型着色；
   - **主板卡片**：CPU0、CPU1、实时环三条折线（实时环上画 1 ms 虚线），4 个实时指标，内存、eth0、中断、温度、内核版本、进程占用；顶栏“实时环正常”chip 按规则变色；
   - **top 视角叠加**（可开关）：画出板上感知的检测框和名称。检测结果由板子随 `observe` 事件一起发出，浏览器把它们画在画面上。
7. **回放模式**：按设计规范 4.6 节实现，并验证：播放任意一次已完成的任务，步骤点可以点击跳转，“回到实时”按钮可用。
8. 在 1920×1080 和 1366×768 两种窗口尺寸下，浅色、深色主题各截一张图，提交到 `sim_agent/docs/img/015-*.png`。

### C. “按图叠放”：仿真端

9. 场景新增第 4 块积木。建议用**橙色**；颜色必须和红、绿、蓝、两个托盘（黄、品红）以及桌面都能稳定区分开，先用感知模块验证。
10. 协议 v1.3（只增加内容，同时更新 `docs/SIM_AGENT_DESIGN.md`）：
    - `reset` 增加可选参数 `layout`，格式是 `{"towers":[["green","blue"],["red"],["orange"]]}`，每个列表从下到上，随机放在桌面上不同的位置，彼此不重叠；
    - 新增 `goal_image`，参数 `{"goal":{"towers":[...]}, "style":"front"}`。用一个**独立的** `MjData` 按目标摆好积木（机械臂移出画面、托盘隐藏），从正面略俯视的角度渲染一张 640×480 的 JPEG 返回。**不能影响正在运行的仿真。**
11. 新建目标图片库 `sim_agent/goals/`：至少 8 个预设（单塔 3 块、单塔 4 块、两座塔等），每个预设一个 JSON 加一张渲染好的 JPEG。另外提供随机生成目标的功能。

### D. “按图叠放”：板子端

12. **目标图片识别** `goal_perception.py`：输入目标图片，输出 `{"towers":[[底…顶],...],"loose":[...],"confidence":0~1}`。方法：颜色分割，按 x 方向聚类成塔，塔内按图像 y 坐标从下往上排序。对 8 个预设图片做测试，必须全部识别正确。也支持用户上传的图片，只要是纯色积木、背景简单就行，尽量识别；识别不确定时，在 UI 上用琥珀色提示，并要求用户确认。
13. **场景感知升级**：现在的感知只能从 top 视角得到 xy，判断不了叠放的顺序。要融合 front 和 side 视角：同一 xy 位置上的积木，按正面图里的高度排序，得到每座塔从下到上的顺序。被挡住的积木，结合上一步执行动作后的预期状态来推断，并标记出来。验收：随机生成 20 种叠放布局，和 `objects` 真值比较，**塔的组成和顺序全部正确**。
14. **工具**：在原有工具基础上：
    - 新增 `update_plan(goal_summary, steps[], reason)`。第一轮必须先调用它；之后每次修改计划也要调用。它**不算动作**，同一轮里允许先调用 `update_plan`，再调用一个动作；
    - 新增 `place_on_table()`：由板子在桌面上找一个空位放下（要避开塔、托盘和机械臂基座附近），返回放下的位置；
    - 保留 `pick`、`stack_on`、`place_in`、`home`、`finish`。
15. **提示词**：交给模型的内容包括：板上识别的**目标结构**（文字），每一轮的**当前塔结构**（文字），以及规则：只能抓最上面的积木；必须先拆开顺序不对的部分；每一步之后对照目标检查。目标图片本身**不发给模型**，任务 009 已经确认它的图片理解不可靠，看图这件事由板子来做。
16. **成功判定**（用真值）：每座目标塔的组成和顺序都正确，同一座塔内相邻两块的 xy 偏差 < 2 cm，高度符合 4 cm 的层高（±1 cm）；不在目标里的积木不能压在任何一座目标塔上。

### E. 验收

17. **按图叠放**场景，每个跑 3 次，每次换一个 seed：

    | 编号 | 初始布局 | 目标 | 考察点 |
    |---|---|---|---|
    | G1 | 4 块都散放在桌面上 | 单塔：蓝·红·绿（自下而上），橙不动 | 读图 + 按顺序搭 |
    | G2 | 绿压在蓝上，红、橙散放 | 单塔：蓝·红·绿 | 先拆再搭 |
    | G3 | 红压在蓝上，绿、橙散放（Sussman 异常的变体） | 单塔：红·绿·蓝 | 经典的规划难题，需要先把红拿开 |
    | G4 | 两两叠成两座塔，顺序都不对 | 两座塔：红·橙、绿·蓝 | 同时处理多座塔 |

18. **基线对比**：写一个不做规划的固定脚本，直接按目标顺序从下往上依次 `pick` 加 `stack_on`，不检查当前状态。G1–G4 各跑 1 次，记录成功与否。这组数据用来说明智能体的价值。
19. **补完任务 014**：T3 用新的 seed 跑 5 次；验证“停止并回位”在执行中途点击后能正确停下并回位。
20. **录屏**：录一段完整的屏幕视频，内容是 G3 的一次成功运行，画面包括浏览器工作台和 MuJoCo 窗口，最好用 1920×1080。视频放在电脑上，在报告里写明路径。另外截 3 张关键帧（初始、重新规划、完成）提交到仓库。

## 附录：SSE 事件格式（板子 → 浏览器）

每个事件一行 JSON，都带 `ts`（板子时间，秒）和 `run`（任务 ID）：

| type | 字段 | 说明 |
|---|---|---|
| `task_start` | `kind`（`instruction` 或 `goal_stack`）、`text`、`goal`（可选：目标结构、图片 URL、识别置信度）、`seed` | 任务开始 |
| `observe` | `scene`（塔结构、各物体的 xy、遮挡情况）、`detections`（top 视角的检测框，像素坐标） | 每次感知 |
| `think_delta` | `text` | 模型输出的文字增量，用于逐字显示 |
| `think_end` | `text`、`tokens` | 一次模型调用结束 |
| `plan` | `version`、`steps[]`、`reason` | 来自 `update_plan` |
| `step_start` | `index`（第几个计划步骤）、`tool`、`args`、`expected_s` | 开始执行一个动作 |
| `step_result` | `ok`、`detail`（例如夹爪宽度、放下的位置、失败原因） | 动作结束 |
| `finish` | `success_self`（模型自报）、`success_truth`（真值评价）、`summary`、`stats` | 任务结束 |
| `sysmon` | 每秒一次：`cpu[]`、`mem`、`net`、`irq`、`procs`、`rt`、`temp` | 主板数据 |
| `alert` | `level`、`text` | 实时环超阈值、API 出错等 |
