## A：运动学优化

同一组 30 个目标点，精度为位置 < 1 mm、姿态 < 1°。模型链由 MuJoCo 导出，没有手抄 DH。

| 实现 | 平均 ms | 最大 ms |
|---|---:|---:|
| 原 Python，冷初值，无 profiler | 1352.059 | 1747.553 |
| 原 Python，热启动 | 632.677 | 1411.038 |
| 缓存变换、向量化雅可比、一次求解两个右端项 | 314.267 | 707.740 |
| 调整阻尼/步长，热启动 | 264.458 | 570.450 |

| C / ctypes，热启动 | 18.068 | 21.848 |

全部 30 点收敛；另以独立 Python FK 检查 30 个随机位姿，最大位置误差 0.886 mm、姿态误差 0.164°，不可达目标和无效种子被拒绝。
上述计时是独立 IK 基准，不代表满负载的在线调用延迟。

原实现 cProfile 的累计耗时前十项：ik 53.324 s、_forward 47.771 s、fk 15.284 s、rotation 14.969 s、numpy.cross 12.557 s、moveaxis 6.235 s、index_tricks.__getitem__ 4.510 s、norm 4.247 s、normalize_axis_tuple 2.973 s、numpy.array 2.602 s。累计时间存在调用包含关系，不能相加。完整原始表见 [profile 日志](../../logs/20261108-014-ik-profile.log)。

## B：四视角与持续刷新

首次完整采样窗口 640.690 s，设定 4 Hz、实际平均 3.827 Hz，四幅图均为 320×240；含智能体运行负载。
图像渲染由独立图形进程完成，物理进程持续运行。窗口结束时看门狗计数为 0、到包间隔最大 14.357 ms。
实时控制处理均值约 0.187 ms，但生命周期峰值 **1.256 ms**，因此 **1 ms 指标失败**。
此前视觉测试也曾出现 1.287 ms，不能只选较好窗口声称通过。
CPU0 在智能体启动和视觉处理中持续满载，之后按任务单降到 2 Hz 继续测试。严格配对的面板开关负载对照尚未完成，不能将不同版本、不同历史记录数量下的空闲采样差直接归因于帧率。

## 失联、偏差与风险

共记录 **7 次**中断：4 次早期准备/剖析阶段、T3 两次、另一次恢复后待命阶段。准确时间、活动及是否属于正式试验见[中断记录](../../logs/20261108-014-interruptions.log)；早期部分只有时间区间，不补造精确时间。

- 未改 Windows 防火墙、Clash、eth1、内核、固件或真实电机；只运行 MuJoCo 控制。
- 运行日志/图像写 RAM 并同步电脑；两次失联均造成正在执行步骤的部分细节未落盘。原始认证/串口会话留在忽略目录，公开证据不含认证交互、口令、API Key、真实 MAC、SSH 主机密钥或私有文档链接。
- native IK、视觉模块和 rt_ctl 的编译产物缓存在电脑忽略目录，恢复时哈希相同；仓库不提交二进制。
- top/front/side 是固定场景观察，腕部视角随夹爪运动，接近物体时只能显示局部；没有保证腕部图像在每个位姿都包含整条机械臂和所有物体。
- 模型曾在遮挡尚未解除时调用 finish；独立真值评价没有接受其自报结果。提示词和工具校验不构成模型一定会遵守视觉确认要求的保证。
- JSON 查询接口的直接响应方式参考 [FastAPI 文档](https://fastapi.tiangolo.com/advanced/custom-response/)，已在板上恢复版本验证；没有足够配对数据声称它修复了性能或失联问题。
