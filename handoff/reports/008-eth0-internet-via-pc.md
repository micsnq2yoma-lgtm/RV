确认 **J1=eth0**，Windows ICS 可自动为板子分配 `192.168.137.178`，板子到 `8.8.8.8` 的 ping 成功；但启用共享时主机 HTTPS 在两种独立客户端中失败，守护已自动回滚，当前 ICS 关闭。SSH/SCP 和 Ubuntu apt 尚未验证，不能把部署通道标为完成。

## 需要回答的问题

1. **电脑上哪块网卡用来上网，哪块接开发板？ICS 是怎么启用的？** 无线网卡上网，有线网卡直连 J1；公开日志使用角色别名，实际名称留本地。用户批准后，由管理员进程对已核实的上游调用 EnableSharing(0)，下游调用 EnableSharing(1)。每轮先精确备份，独立回滚进程心跳确认递增后才触发，不取消已有其他共享；基线没有其他共享。成功条件不成立，因此未保留 ICS。
2. **板子的 eth0 拿到了什么 IP？是 DHCP 自动分配的还是手动配的？** 当前启动自动 DHCP 获得 `192.168.137.178/24`；较早启动为 .26。后台 udhcpc 与 sshd 在运行。回滚后租约仍在板子 RAM 中，但电脑网关已不存在。
3. **板子到电脑、到外网 IP、到域名，三项 ping 的结果分别是什么？** 网关 3 发 0 收；8.8.8.8 为 3 发 3 收，平均 55.472 ms；github.com 返回 Fake-IP 范围的 `198.18.1.137`，3 发 0 收。不能由域名查询返回地址推断互联网业务成功；网关无 ICMP 回复原因未确认，未关闭防火墙。
4. **电脑能否 SSH 和 SCP 到板子？board_ssh.ps1 能不能用？** 未确认。本轮没有真实 SSH/SCP 会话。两份脚本完成静态语法/参数检查，不包含密码，实际登录、文件完整性和远端退出码传递仍待网络恢复后验证。
5. **校时用的是什么方法？** 镜像没有 ntpd，使用主机 UTC 的 date -u -s 回退并读回验证。未设置 RTC，重启后保时未确认。
6. **Ubuntu 的 apt-get update 能否成功？git 装上了吗？** 未确认，本轮未尝试。实际软件源未读取，也没有安装 git 或 ca-certificates。任务 007 的历史结果为 git 不在 PATH；不能当作本轮新验证。
7. **板子重启之后，哪些设置需要重新做？** 重新确认 J1 链路、主机 ICS 状态、DHCP 地址/路由/DNS、SSH 主机身份及时间。内存 rootfs 改动和未来部署的认证公钥不能依赖跨重启保留。Ubuntu 要重新 start，结束后 exit/stop；详细命令见 NETWORK.md。

## 和任务单不一致的地方

- 为满足本机网络规则，在 ICS 前添加精确配置备份、独立守护、心跳验证、主机 HTTPS 与临时独立 Chrome 对照。保护配置包括主机上游 IP/DNS、其他路由、TUN、代理、Clash 文件哈希和防火墙；没有主动修改它们或共享服务。
- 自动 UAC 提示多次不可见/被取消，最终由用户在管理员 PowerShell 中运行本地准备程序。期间缺少 COM3/有线载波，待用户恢复接线后才继续；没有把空串口采集当成启动失败。
- 较早复核的独立探测启动晚于回滚，没有当作共享活跃证据。最终轮先启动观察进程、确认就绪后再启用共享，串口、两种 HTTPS 客户端和 Chrome 的时间戳可相互对应。
- 共享期间主机 HTTPS 失败，按照本机“主机网络稳定优先”的要求停止本轮联网推进。C7、C8 实机验证和 E 节软件操作未完成；D 节通过无需网络的回退方式完成。
- Windows 主机脚本按本任务要求使用 PowerShell；板上命令使用 POSIX sh。没有改变启动文件、eth1、EtherCAT 或电机状态。

## 发现的问题和风险

1. **主机异常可重复出现。** 最终轮中，Windows PowerShell 5 的 Microsoft/GitHub HEAD 各连续三次超时（主机日志第 246–251 行）；同时 PowerShell 7 对三个 HTTPS 站点报告 TLS unexpected EOF（第 265–268 行），独立 Chrome 报 ERR_NETWORK_CHANGED（第 270–273 行）。板子到外网 IP 同时成功。证据表明所测主机 HTTPS 路径受影响，但具体 ICS/TUN/DNS 交互根因未确认，不能归因于某一个组件。
2. **最终回滚成功。** 守护在 `03:03:51Z` 记录共享关闭、原下游 DHCP/DNS 恢复、保护状态与当轮备份一致。随后三个站点的新 Windows PowerShell 5 HEAD 全部 200（第 275–278 行）。收尾只读复核中，下游原配置、保护网络字段一致，诊断进程全部退出（第 280–301 行）。
3. **回滚后 Clash 文件哈希发生后续变化。** 最终较晚复核与快照仅 ClashHashes 字段不同，来源未确认；没有用旧文件覆盖当前配置。代理、TUN 状态、DNS、路由和防火墙等其余受保护字段一致。不能把较晚快照声称为逐字节完全相同。
4. **早期回滚实现曾出错，已如实保留。** 首轮保护状态比较触发停止，原始差异未完整定位；关闭两项共享后，临时无 IPv4 导致恢复脚本异常。后续修正空地址处理、自动 metric 恢复及动态字段/跨版本序列化比较，经管理员恢复核对通过，后续三轮均收尾 rolled-back。首轮错误与 RECOVERY_VERIFIED 见主机日志第 125–160 行。没有绕过联网失败判据或延迟失联回滚。
5. 当前仍有板子租约和 DNS 指向已关闭的共享网关；这不是可用联网状态。若要继续，不应盲目重启相同共享或擅自调整主机 DNS/TUN/代理/防火墙。
