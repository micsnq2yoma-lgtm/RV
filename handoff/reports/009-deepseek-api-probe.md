## 需要回答的问题

1. **准确模型ID、列表？** `/models` 返回 `deepseek-flash`（显示名DeepSeek-V4.1-Flash）和 `deepseek-v4-pro`（DeepSeek-V4-Pro）。没有 `DeepSeek-V4.1-Flash-1017`。经用户当次选择实测 `deepseek-flash`，不能宣称测试了1017固定快照。
2. **工具、JSON、图片？** 工具：首测及后续5次均正确调用pick(color=red)。JSON：正确返回并解析目标对象。图片：接口接受image_url/base64 PNG并返回200，但本次答White而不是red；仅能确认格式接受，不能判断是否忽略图片或证明可靠视觉能力。输入已用独立Pillow解码确认64×64 RGB、所有像素(255,0,0)，SHA256为ca96adb50da6a5f6cbfe03c9c5eb8ad8f1a6c88f526b8a4b9d9d7d3b9ef90157。
3. **板上工具调用平均/p95？** 5个成功样本，均值1.2131567292秒，nearest-rank p95=1.5825594430秒（5样本时等于最大值）。这是Ubuntu客户端经SSH代理的端到端请求耗时，不是模型纯推理时间；小样本不能代表长期尾延迟。
4. **token用量？** 5次总token为475、465、463、472、445，平均464，范围445–475；每次prompt389，其中缓存命中255；completion分别86、76、74、83、56。缓存、推理内容和提示词会影响后续费用/延迟，不外推固定成本。
